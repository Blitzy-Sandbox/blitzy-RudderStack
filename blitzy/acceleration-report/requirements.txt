# Python dependency manifest for blitzy/acceleration-report/scripts/
# Analysis environment only. Not consumed by rudder-server runtime, build, or CI.
# Pinned versions per AAP §0.4.2 — match exactly for deterministic re-runs (Rule 5).
#
# Security-vetted pins (see decision-log.md DL-014 and DL-038):
#   - requests==2.32.5 addresses CVE-2024-47081 (netrc credential leak via
#     malicious URL; the upstream fix landed in 2.32.4 — bumping from 2.32.3
#     to 2.32.5 picks up that fix plus subsequent bugfixes).
#     NOTE: CVE-2026-25645 (insecure temp-file reuse in
#     ``requests.utils.extract_zipped_paths()``) is NOT fixed at 2.32.5 — the
#     upstream fix only landed in 2.33.0. The CVE is documented here as
#     non-exploitable in this codebase because no script under
#     ``blitzy/acceleration-report/scripts/`` calls ``extract_zipped_paths``;
#     verified via ``grep -rn extract_zipped_paths scripts/`` returning zero
#     matches. Standard ``requests.get`` / ``requests.post`` usage is not
#     affected by CVE-2026-25645 per the upstream advisory (GHSA-gc5v-m9x4-r6x2).
#     See decision-log.md DL-038 for the CP-FIN-5 documentation correction.
#   - jinja2==3.1.6 addresses CVE-2024-56201, CVE-2024-56326, and CVE-2025-27516 vs 3.1.4
#   - defusedxml==0.7.1 provides the safe XML parser used by 06_extract_ci_history.py
#     when ingesting JUnit XML artifacts from GitHub Actions (semi-trusted input).
#     Replaces the stdlib xml.etree.ElementTree calls that were flagged in the CP3
#     security review; defusedxml disables XML External Entity (XXE), billion-laughs,
#     and external-DTD expansion by default.
#   - PyYAML==6.0.2 is the structural parser used by 07_extract_exceptions.py to
#     read .snyk policy files. The script previously imported PyYAML lazily without
#     declaring it, causing manifest drift. Declaring it removes the regex-only
#     fallback path while leaving the legacy fallback in place for environments
#     where PyYAML is intentionally absent.
#
# Transport-extras pin (see decision-log.md DL-023):
#   - gql[requests]==3.5.0 declares the `[requests]` extra alongside the base
#     gql pin. The `[requests]` extra installs `requests-toolbelt`, which is
#     required by `gql.transport.requests.RequestsHTTPTransport` — the
#     synchronous HTTPS transport used by scripts/08_extract_linear.py to
#     execute Linear GraphQL queries. The earlier `gql==3.5.0` pin (without
#     the extra) installs the gql package itself but does NOT pull in
#     `requests-toolbelt`, so a clean-machine `pip install -r requirements.txt`
#     against a venv with no other Python packages installed would succeed
#     but `import gql.transport.requests` would later fail at runtime in
#     08_extract_linear.py with `ModuleNotFoundError: No module named
#     'requests_toolbelt'`. The current pin closes that gap; the Linear
#     extractor's no-op path (when LINEAR_API_KEY is absent) is preserved
#     because the lazy-import block continues to handle ImportError gracefully.
#
# All other pins remain at AAP §0.4.2 baseline; no known critical CVEs at review time.
